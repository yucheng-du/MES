# 设备状态接入

[English](EQUIPMENT.md) · 简体中文

在“设备台账 → 采集设备编号”填写唯一设备号，并在服务端配置 `MQTT_URL`、`MQTT_USERNAME`、`MQTT_PASSWORD` 和 `MQTT_TOPIC`。凭据留在服务端，不返回给浏览器或 Android 网页。默认订阅 `device/send/+`，主题的最后一段标识设备。

## 消息格式

支持传统设备消息格式：主题 `device/send/CNC001`，消息 `{"RGY":3}`。对应关系为 `0 → offline`（停机）、`1 → fault`（故障）、`2 → idle`（待机）、`3 → running`（运行）。缺少设备时间的消息以服务器接收时间计时，不能追溯离线期间的精确状态。

推荐事件格式：

```json
{
  "eventId": "CNC001-00001234",
  "status": "running",
  "occurredAt": "2026-10-14T09:30:00+08:00"
}
```

状态支持 `offline`、`idle`、`running`、`fault` 和 `maintenance`。事件 ID 必须在设备内唯一；相同 ID、相同内容重投不会重复写入，内容不同会拒绝。同设备的晚到事件进入历史但不回退最新状态，日汇总按实际事件时间重算。大于当前时间一分钟以上的事件会拒绝，应校准设备时钟。

设备编号与已有台账对应，未知设备不会自动建档。入站消息最大 16 KiB，按设备串行处理。传统格式连续相同状态视为心跳，更新最后通信时间而不积累重复的状态记录。

## 日报与验证

日报按 `FACTORY_TIMEZONE`（默认 `Asia/Shanghai`）计算。没有先前状态依据的时间段标为 `unknown`，不会伪造为运行或停机。数据过期提示与已记录状态是两回事：停止通信本身不会生成 `offline` 事件。运行时长是状态统计，不直接等同于 OEE；OEE 还需要计划时间、理想节拍和质量口径。

管理员和生产主管可以先用设备页面的手工状态登记验证视图，手工登记写入审计日志。真实采集仍须用现场设备核对消息与时间。

生产连接默认要求 MQTT TLS（`mqtts:` 或 `wss:`）；可信私网使用明文 broker 时需显式设置 `ALLOW_PRIVATE_MQTT=true`，该设置不适合公网传输。

设备接口见 [API 合同](API-CONTRACT.zh-CN.md)。本地协议或数据库测试不代表已验证实际设备、broker 或生产网络的兼容性。
