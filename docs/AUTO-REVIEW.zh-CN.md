# 报工自动审核

[English](AUTO-REVIEW.md) · 简体中文

自动审核作用于已经完工的报工及其计件工资。服务端定时检查正常记录并入账，需要确认的记录进入人工队列，保留具体原因。关闭网页或 Android 客户端不影响后台执行。

## 设置入口与默认值

管理员或生产主管在“报工审批 → 自动审核设置”中配置，保存后生效，设置持久化到数据库。

| 设置                   | 默认    | 含义                                                                                   |
| ---------------------- | ------- | -------------------------------------------------------------------------------------- |
| 自动审核               | 开启    | 关闭后停止自动批准，人工审批仍可使用                                                   |
| 等待时间               | 5 分钟  | 从报工完工时间开始计算，期满后参加检查                                                 |
| 单笔金额上限           | 2000 元 | 按工单快照单价计算；超过上限交人工                                                     |
| 最低用时比例           | 0%      | 默认不检查标准节拍；例如设置 10%，实际加工用时低于“标准分钟/件 × 完工数 × 10%”时交人工 |
| 要求收料与完工数量一致 | 关闭    | 默认允许正常分批完工；开启后数量不一致交人工                                           |

后台每 60 秒检查一轮，启动时会补查到期报工。“立即检查”使用同一套规则，不绕过等待期或停用开关。因此默认 5 分钟等待期后，通常在下一分钟内处理。

首次启用和重新启用时会记录生效边界。此前已完工的积压记录继续由人工处理，不因开启开关直接批量计薪。修改等待时间或金额等规则会影响尚未被判定异常的新报工；已经转人工的记录仍留在人工队列。

## 哪些记录需要人工

- 曾经被人工驳回，随后重新提交的报工；历史驳回记录也会从审计中识别。
- 工单已关闭、操作员已停用，或同工单存在待审/已批准的报废。
- 完工数量为零、数量或开始/完工时间不符合约束。
- 超过配置金额上限，或未满足已开启的数量一致性、最低用时检查。
- 自动审核启用前完工的历史记录。
- 工资来源重复、金额或数据库业务约束冲突等无法自动确认的执行异常。

“转人工”不会把报工退回给员工，不撤销已经记录的物理完工。主管或质量人员可以查看原因并继续人工批准、退回。工资只在批准时生成，正常报工不再需要逐条点击。

## 执行与追溯

列表区分自动批准、人工批准、等待自动检查和需要人工确认，显示人工处理原因。设置页提供待处理汇总及最近一轮执行结果。自动审批以“系统”记录审批来源、规则版本和执行批次；人工审批仍记录实际审核人。

自动与人工复用单笔审批事务，报工状态、工资分录和审计一起提交。重复跑批、多个服务进程或与人工审批同时执行，都不会重复计薪。连接中断、超时、死锁等暂时故障会记录为执行失败，未成功的记录在恢复后继续检查；确定的工资来源或业务约束冲突会转人工。两类错误都不会被当作审核通过。

配置停用与单笔审批协调：已开始的单笔事务先完成，停用成功返回后，后续记录不能继续按照旧配置自动批准。

本功能不自动批准报废、质量检验或其他管理台账；这些业务继续使用各自的责任人与审核流程。
