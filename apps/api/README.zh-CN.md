# MES API

[English](README.md) · 简体中文 · [项目说明](../../README.md#简体中文)

使用 Fastify 5、TypeScript、PostgreSQL 17 的模块化单体，需要 Node.js 22.12 或以上。公开接口及参数见 [API 合同](../../docs/API-CONTRACT.zh-CN.md)。

## 本地开发

以下命令均在**仓库根目录**执行。根脚本加载根目录 `.env`；直接调用工作区服务器脚本不会自动加载该文件。

```bash
npm ci
npm run db:local
npm run db:migrate
npm run db:seed
npm start
```

本地数据库工具要求 PostgreSQL 命令行程序在 `PATH` 中，会创建开发库和测试库，仅在 `.env` 不存在时写入。也可将根目录 `.env.example` 复制为 `.env`，分别配置 `DATABASE_URL` 和 `TEST_DATABASE_URL` 后运行迁移与 seed。Seed 创建公开的开发演示数据，在生产环境拒绝执行，已有用户时跳过。

`npm start` 仅启动 API，`npm run dev` 同时启动 API 和网页。示例环境使用 API 端口 4300；未配置 `HOST`、`PORT` 时，服务器默认监听 `127.0.0.1:3000`。

生产先运行迁移，并按 [部署指南](../../docs/DEPLOYMENT.zh-CN.md) 创建私有管理员。初始化可选 `ADMIN_USERNAME`、`ADMIN_NAME`，必须显式提供至少 12 位的 `ADMIN_PASSWORD`；已有管理员时拒绝重复初始化。`NODE_ENV=production` 要求 HTTPS `APP_ORIGIN` 和 Secure Cookie。容器需配置 `HOST=0.0.0.0`，只有位于可信反向代理后才开启 `TRUST_PROXY=true`。不要将 seed 演示数据库作为生产环境公开。

## 验证

在仓库根目录执行，先在 `.env` 配置 `TEST_DATABASE_URL`：

```bash
npm run typecheck
npm test
npm run test:integrations
```

数据库测试拒绝名称不以 `_test` 结尾的连接，会重建专用库的 `public` schema；不要与其他测试进程或业务环境共用该库。测试使用真实 PostgreSQL，覆盖多连接竞争、工资故障注入和事务回滚。准备步骤及验证边界见 [测试说明](../../docs/TESTING.zh-CN.md)。

## 业务与安全约束

- 写请求校验来源；会话使用随机 256 位令牌，数据库只存哈希，12 小时有效。密码使用 scrypt，登录限流；停用用户、修改角色或重置密码会撤销会话。
- 服务端检查角色和记录归属。操作员操作本人报工、读取本人薪酬；工资奖励和扣款只由审批用例生成。
- 工单保存工艺和单价快照。工序按序推进，部分完工继续当前工序；本人或主管可重提被驳回报工，不改变生产数量。
- 成品库存以销售订单和产品为粒度，备库使用独立的空订单余额。并发变更锁定余额行，禁止跨订单出库、负库存和超出完工量入库。
- 生产、库存等指定动作携带 `requestId`；相同内容重试返回原结果，同键不同内容拒绝。审批、工资和审计在同一事务提交。
- 报废需质量人员或主管审批，不能直接减少已入库的完工产量。审核人可显式指定扣款/奖励单价，默认均为零；全数报废后允许零良品完工。
- 共享定义校验台账字段、关联存在性、修订号和状态转换。原材料/辅料入出库审批实际更新库存；工时及安全奖惩审批生成来源唯一的工资分录；每人每天已批准计时工时不能超过 24 小时。
- 工作任务和安灯提交后，须由受派人或主管正式反馈才能批准。草稿预填结果或上一轮反馈不能绕过办理；反馈记录办理人、时间、修订号及审计事件。
- SSE 仅向登录用户发缓存失效通知，不发送业务详情；重新查询再次校验权限，每 15 秒检查会话有效性。MQTT 通过独立集成模块注册。
- `POST /api/files` 接收 multipart 附件，管理员、主管和质量人员可上传；登录用户通过认证接口获取元数据和下载。作业文件最多引用 10 个已有附件。文件内容保存于 `FILE_STORAGE_DIR`，数据库保存元数据和校验和，备份须包含二者。

## 报工自动审核

默认开启，等待 5 分钟，单笔上限 2,000 元，允许分批完工，标准节拍检查关闭。管理员/主管通过 `GET/PATCH /api/settings/auto-review` 携带当前修订号配置：等待时间 0–1440 分钟；金额上限为正数、最多两位小数、不超过 1,000,000,000；用时比例为 0–1；可选要求收料和完工数量一致。`POST /api/settings/auto-review/run` 检查一次，仍遵守开关和等待期。

API 在启动时和每 60 秒执行检查。测试中的 `createApp()` 默认不启用任务，由服务器入口显式开启。多实例使用数据库会话锁选取执行者；单笔审核按“配置 → 工单 → 报工 → 人员”加锁，并共用人工审批事务。工资来源唯一约束防止重复计薪。停用会等待在途审核，服务器关闭会等待已开始的审核事务结束。

只有当前启用边界后完工的报工有自动资格。此前积压、驳回重提、工单关闭、人员停用、数量/时间无效、同工单待审或已批准报废及超出阈值的记录交人工；规则放宽不会清除转人工标记。迁移从审计中恢复历史驳回标记。原因保留中文源文，在英文界面由 Web 消息目录翻译。

执行记录保留来源、规则版本、批次及逐笔结果。确定的工资来源或业务约束冲突回滚并转人工；数据库连接、超时、死锁等暂时故障保留自动资格，后续重试。设置页和首页展示队列汇总与执行结果，`GET /api/reports?reviewMode=manual|automatic|pending_auto` 筛选对应队列。操作行为和范围见 [自动审核说明](../../docs/AUTO-REVIEW.zh-CN.md)。

## 源码入口

- `src/production.ts`：生产与成品库存。
- `src/report-review.ts`：共用审批计薪事务。
- `src/auto-review.ts`：配置、规则判定及后台执行。
- `src/catalog.ts`：管理台账与审批联动。
- `src/auth.ts`：认证授权。
- `src/db.ts`：事务与幂等。
- `src/integrations.ts`、`src/files.ts`：设备接入和认证附件。

SQL 值使用参数化，动态表名和排序只来自代码内静态允许列表。容器部署、实际设备和打印仍需目标环境验收，本地测试不代表这些现场结果已成立。
